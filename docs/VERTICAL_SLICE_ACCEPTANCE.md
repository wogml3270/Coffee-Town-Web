# Phase 1–2 Vertical Slice 완료 조건

## 플레이 흐름

- [ ] 첫 화면에서 게스트 또는 로그인 사용자가 영업을 시작할 수 있다.
- [ ] 카페 플레이 화면이 가로·세로 모바일 화면에서 잘리지 않는다.
- [ ] 조이스틱 또는 키보드로 캐릭터가 상하좌우로 이동한다.
- [ ] 가까운 상호작용 대상이 명확하게 강조된다.
- [ ] 작동 버튼으로 재료를 집고, 기계에 놓고, 결과물을 다시 집을 수 있다.
- [ ] 원두 → 분쇄 → 추출 → 온수 → 서빙 순서가 실제 오브젝트 이동으로 표현된다.
- [ ] 잘못된 기계 또는 순서에는 상태를 변경하지 않고 즉시 피드백을 준다.
- [ ] 주문 완료 시 골드와 XP가 증가하고 다음 주문이 표시된다.
- [ ] 제한 시간 종료 후 결과 화면으로 이동한다.
- [ ] 나가기 또는 새로고침 후에도 확정된 진행도만 복원된다.

## 에셋 최소 세트

- [ ] 캐릭터 idle 4방향
- [ ] 캐릭터 walk 4방향
- [ ] pick, place, repair 동작
- [ ] 카페 배경과 이동 가능 영역 마스크
- [ ] 기계 5종의 기본/활성/완료 상태
- [ ] 원두, 분쇄 원두, 에스프레소, 온수, 완성 음료 아이콘
- [ ] 선택 강조, 제조 진행, 성공, 실패 이펙트

## 기술 품질

- [ ] `npm run verify`가 통과한다.
- [ ] 핵심 제조 상태 전이에 단위 테스트가 있다.
- [ ] Playwright로 게스트 시작 → 주문 완료 → 결과 화면 흐름을 검증한다.
- [ ] 중급 모바일 기기 기준 플레이 중 50 FPS 미만으로 장시간 하락하지 않는다.
- [ ] 초기 JavaScript gzip 크기를 측정하고 큰 에셋은 지연 로딩한다.
- [ ] API 키와 service-role 키가 브라우저 번들 및 Git에 포함되지 않는다.

## 배포 품질

- [ ] Pull Request마다 GitHub Verify와 Vercel Preview가 성공한다.
- [ ] Preview에서 `/`와 `/auth/callback`이 SPA rewrite로 열린다.
- [ ] `main` 병합 후 Production이 Ready 상태가 된다.
- [ ] Production 환경의 Supabase Auth와 공개 catalog 조회가 HTTP 200을 반환한다.
